# chat-relay 工作规程

> `/chat-relay` 开启后，做备料、回程、表态、收敛前读本文件；开关与入口行为见本 skill 的 `SKILL.md`。

## 定位

- 执行侧（agent）的训练方向是执行与执行轨迹：协议写得清楚，面向人的表达却压缩、自造词、电报句。
- chat 的训练方向是人类偏好。于是把「需要人参与理解」的内容整条线交给 chat，把 chat 当作**与用户同等重要的人**：用户能直接读仓库文件，chat 不能——凡 chat 本轮需要知道的，都在备料时复制进上传包，不让它猜。
- 本模式是附加层：不修改任何既有 skill 的条文，只在其「面向人的内容产出」环节做接管——类似计划模式：先分析，不先动手。

## 什么走 chat 环

**一切以 chat 为主场**：读懂／讲解／讨论／判断／取舍／改写成稿——凡「要给用户看、要让用户理解、要用户拍板」的内容产出。

**分流边界（2026-10-12 用户裁定）：内容走 chat，运行走执行。** 需要人理解与判断的内容（讨论、讲解、取舍、成稿）与**需要独立判定者的锚定判读**（如 DA-1 人工锚点）走本通道；判读／编码／计算等**生产数据的执行性运行**（可复算、可复跑、可对照）**不走本通道**——由执行侧启动对应 skill（research-executor 等）完成。

不走：纯操作面（跑脚本、读写文件、状态查询、材料搬运、格式转换）。

## 一个 chat 环的标准动作

**1. 先分析**（读真实工件；归属 skill 的加载协议照走）：

- 本轮要人理解／判断的是什么；
- chat 的产出要什么形态（如需装回原结构：保留哪些标题与结构）；
- **不可丢失清单**（具体列出，不写空话）：承重含义、限定条件、证据链、既有裁决；
- 术语表：材料里的自造词 → 平实解释。

**2. 备料**（2026-10-10 用户订正：**上传包以复制为核心**）：

- 建会话目录 `topics/<选题>/chat-relay/{YYYY-MM-DD}-{slug}/`（会话归对应选题；平铺与分组布局通用）；
- **选材**——备料的核心判断：先想清楚「chat 完成本轮任务需要看到哪些文件、看到什么程度」，把它需要的源文件列成清单（用户能直接读到的仓库上下文，等价地带给它）。**宁多勿少**：上下文不足是本模式的主要风险，chat 的容量足够容纳足量材料。例：改写契约的会话，至少含契约全文、研究承诺、全部被涉及卡片的卡文（`card.md` 全文）、来源记录（工坊日志相关条目原文）——而不是它们的摘录。
- `提示词.md`（模板 `templates/prompt.md.template`）——自包含：chat 不知道仓库的存在；只写导读（这是什么、怎么读、要什么产出）与材料本身读不出的约定，不转述材料内容。**不写「用法」行**——文件怎么使用、产出怎么带回，属终端交接话术（见下「交接」），不混进给 chat 的正文（2026-10-11 用户裁决）。
- `上传包/`：把选定的文件（或其完整节）**原样复制**为 `F1-简称.md`、`F2-简称.md`……（**副本，原件不动**）：
  - **不用摘要、摘录、重组代替原件**——那是替 chat 节食，把它的视野压到 agent 的筛选范围里；agent 不替它筛内容。需要「某卡的关键条」这类视图时，复制整份源文件（如卡的 `card.md` 全文），不重编条目。
  - 只为可读做形式处理（编号、合并同类文件、加出处标注）；大文件确需裁切时保留完整段落、注明裁切范围，不改写被保留的文本。
  - **单次上传上限 20 份**（2026-10-10 用户指正）：ChatGPT 一轮最多接收 20 个文件——选材超过时按同类**合卷**压到上限内（四文件合卷〔概念卡／论证／账本／变更史〕、账本＋速览合卷、账本＋变更史合卷等），卷内以分隔标题与出处标注区分原件。合卷是为过上限的形式处理，**不因此删材料**。
- `台账.md`（模板 `templates/ledger.md.template`）。

**3. 交接**（终端只说操作面，一句到位）：

> 打开 `topics/<选题>/chat-relay/{slug}/`：把 `上传包/` 里全部文件拖进 ChatGPT，`提示词.md` 全文贴过去；讨论完点分享把链接贴回来（或把产出存进 `回报/`）。

**4. 回程**：

- chat 索取材料或提问 → 用户转达 → 补进上传包（编号顺延）或给可直接转达的答复 → 记台账；
- **用户贴回分享链接**（`https://chatgpt.com/share/...`）→ 脚本直接落盘，不经 agent 二次写入：

  ```bash
  uv run python .reasonix/skills/chat-relay/scripts/fetch-share.py "<链接>" \
    --drop-prompt "topics/<选题>/chat-relay/{slug}/提示词.md" \
    --output-dir "topics/<选题>/chat-relay/{slug}/回报/"
  ```

  - 第二轮起 `--drop-prompt` 用 `提示词-r{N}.md`；回报文件名由脚本顺延为 `r{N}.md`。
  - 落盘范围自本轮提示词之后：提示词是第一个用户输入、我们已有，连同之前轮次一并裁除——多轮只落本轮新增，不重复堆积。
  - 提示词在会话里匹配不到即报错——多半链接还是旧快照（未含本轮）或提示词尚未贴出，请用户核对后重试。
  - 链接为匿名公开（任何人持链可读）；内容敏感的会话不用此路径，仍走粘贴带回。
  - 分享页的消息模型与落盘格式（为什么不是「一问一答」、静默帧、伪影、围栏）见 `references/chatgpt-share-format.md`。
- 产出带回（粘贴或存入）→ 落 `回报/r{N}.md` → 进入表态。

**5. 表态（必须）**——三轴核对：

| 轴 | 查什么 |
|---|---|
| 保真 | 承重含义、限定条件、证据链：丢了没有？强度被改了没有？ |
| 事实 | 与仓库现状、既有裁决冲突没有？ |
| 可装回 | 格式能否直接落位（结构、标题、落点）？ |

- **同意** → **立即实施**：写进它的归属处，走归属 skill 的现行写入契约（本 skill 不另造写入路径、不绕写入守卫）。
- **反对** → 写 `提示词-r{N+1}.md`：具体到句（哪句话、丢了什么、撞了哪条事实或裁决）——这就是带回 chat 的文本；用户带回，开下一轮。

**6. 收敛**：实施完毕，台账记结果，会话收尾。

## 会话状态与恢复

- 台账状态词：等带去／等带回／待表态／待实施；报告时同时给「等谁」。
- 状态查询（`/chat-relay status`）只读报告，不推进工作。
- 恢复只在用户给出信号后进行（2026-10-10 裁决：不预先全库扫）：
  - 用户说「继续」→ 扫描各选题 `chat-relay/*/台账.md`（`topics/` 下全部选题，平铺与分组两态布局通用），接最近一个未收敛的会话；
  - 用户带回产出 → 落到用户指到的话题的 `回报/r{N}.md`，进入表态。

## 轮次纪律

- chat 产出与 agent 表态成轮成对（`回报/r{N}.md` ↔ 台账轮次行）；**没有表态不进入实施**。
- 反对必须具体到句；含糊的反对白烧一轮。
- 多轮不收敛：停下问用户（换材料、换问法，或用户直接拍板）。

## 会话目录

```
chat-relay/                        # 仓库根：仅开关（gitignored）
└── ON                             # 开关（存在＝开启）

topics/<选题>/chat-relay/          # 会话归对应选题（分组布局 topics/<组>/<选题>/ 同）
└── {YYYY-MM-DD}-{slug}/
    ├── 提示词.md                  # 贴给 ChatGPT；第二轮起：提示词-r2.md…
    ├── 上传包/                    # F1-简称.md、F2-简称.md…（副本）
    ├── 台账.md                    # 状态、材料、轮次、实施记录
    └── 回报/                      # r1.md、r2.md…（chat 产出落盘）
```

## 边界

- **不写研究工件**：只写开关（仓库根 `chat-relay/`）与各选题的 `chat-relay/` 会话工作区；实施经归属 skill 契约。
- **不替用户谈**：agent 的意见只以「表态」与「下轮提示词」两种形态进出 chat 环。
- **不改既有 skill**：附加层，不修改任何 skill 的条文。

## 模板与脚本（均在本 skill 目录下）

- `templates/prompt.md.template` — 给 chat 的提示词骨架
- `templates/ledger.md.template` — 会话台账骨架
- `scripts/chat-relay.sh` — 开关读写＋钩子检查
- `scripts/fetch-share.py` — 回程落盘：分享链接抓取转 markdown，直接写 `回报/`（取自 chatgpt-share-md，MIT）
- `tests/test_chat_relay.py` — 脚本行为测试
- `tests/test_fetch_share.py` — fetch-share 离线测试
