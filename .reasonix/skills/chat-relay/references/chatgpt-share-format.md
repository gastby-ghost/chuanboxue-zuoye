# ChatGPT 分享链接回程：格式说明

> 分享链接回程（`scripts/fetch-share.py`）产出的 `回报/r{N}.md` 长什么样、为什么，做表态与落位时按此判读。回程流程本身见 `protocol.md`。

## 来源与获取

- 只认**公开分享链接**（`https://chatgpt.com/share/...`）；私人 `/c/...` 会话地址读不到。
- 抓取要出网：本项目经 `.env` 里的代理（脚本自动读取，无需手设）；终端直连不通时没有代理必失败。
- 内容取自分享页内嵌的会话数据（React Router 流载荷），不是页面渲染结果。
- 页面载荷结构变化时解析**响亮报错**（找不到载荷），不会静默漏半份内容；此时可退回：让用户在浏览器把分享页「另存为」HTML，脚本同样接受本地文件输入。

## 消息模型：为什么不是「一问一答」

ChatGPT 的真实消息序列不等于一个用户配一个助手：

- **一个用户回合内，助手可以连发多条消息**：进度消息（「我会按…」「目前骨架…」）与正式产出各是独立消息，中间夹着几十到上百条工具调用帧。网页把它们渲染成一个连续回合——界面上像一问一答，导出后边界才露出来。
- **工具调用、系统消息、空帧，分享页对第三方全部隐去**（`metadata.is_redacted`）——一段长会话里静默帧常有一两百条，转换器默认一概不落。
- **落盘保留**：用户消息（本轮提示词按裁除处理）＋助手全部有文消息，**包括中间进度消息**。这些中间消息不是噪音——它们记录 chat 的思路、保留意见与自我更正，表态要读。
- **回合边界＝下一条 User 消息**。同一回合的多条助手消息会各占一个 `## N. Assistant` 小节，连续出现是原样，不是异常。

## 落盘长什么样

```
# 会话标题
- Source / Conversation ID / Created / Updated / Messages / Fetched / 裁除说明…
## 1. Assistant      ← 本轮提示词被裁除；文件从第一条助手消息起
## 5. User           ← 回合内的用户追问、确认原样保留
## 6. Assistant
```

- `## N.` 是**落盘后**的连续序号（裁除后从 1 起），不是 ChatGPT 内部编号。
- **附件（上传包文件等）不出现在回程文本里**——分享页只带对话文字，材料本体执行侧自有。
- 行内引用标记（ChatGPT 私有区字符、citeturn 类 token）已剥除；正文中的 `:::writing{...}` 围栏是 ChatGPT 的产物标记，**落位实施时应剥除**。
- 时间戳只有会话级的 Created/Updated；消息级不落。

## 贴出文本与提示词文件的出入（裁除匹配按相似度）

从渲染页复制粘贴会带伪影，贴进 chat 的文本常与 `提示词.md` 不逐字一致：

- 首部标题与「用法」行一般不被贴出；
- 粗体标记前一个字被实体化：`只` → `&#x53EA;`；
- 标记转义并加倍：`**准备能力**` → `**\*\*准备能力\*\***`；连字符被转义：`- ` → `\- `。

因此 `--drop-prompt` 按**归一相似度**（解码实体、去转义与强调符、去空白后 ≥85%）定位本轮提示词，不逐字匹配；整条会话都找不到时报错——多为链接还是旧快照（未含本轮）或提示词尚未贴出。伪影随提示词一并裁除：实测一案 64 处实体全部落在提示词消息内，落盘正文零伪影。
